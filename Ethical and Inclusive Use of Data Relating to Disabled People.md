# Ethical and Inclusive Use of Data Relating to Disabled People

## A Guidance Framework for Accessibility, Privacy, Dignity and Trust

**Executive Summary**

Organisations need data to understand whether products, services and experiences are accessible. Without data, accessibility decisions become assumptions, and the principle of "Nothing About Us Without Us" cannot be meaningfully applied.

However, data about disability can be sensitive, identifying, and vulnerable to misuse. The ethical challenge is therefore not whether accessibility-related data should be collected, but how it should be collected, governed, used, shared and protected.

This guidance promotes a model in which:

- Accessibility data is collected to improve experiences, not to profile individuals.
- Aggregate insight is preferred over individual tracking.
- Privacy, dignity and autonomy are treated as accessibility requirements.
- Disabled people participate in governance and decision-making.
- Data collection is proportionate, transparent and evidence-based.
- Accessibility improvements are validated across multiple user groups.
- Equivalence of experience is the primary objective.
- Disability is never used as a justification for excessive surveillance, profiling or commercial exploitation.

The ultimate goal is to generate trustworthy insight that improves accessibility while protecting the rights, freedoms and dignity of individuals.

# Core Ethical Principles

## 1. Nothing About Us Without Us

Accessibility decisions should be informed by disabled people.

This principle does not require organisations to collect extensive personal information about every disabled individual. Rather, it requires meaningful engagement with the communities affected by decisions.

The objective should be:

- Insight about communities.
- Insight about barriers.
- Insight about outcomes.
- Insight about experiences.

Not:

- Detailed monitoring of individuals.
- Behavioural profiling of disabled people.
- Surveillance-based personalisation.

The organisation's responsibility is to understand accessibility impacts, not to identify or track individual disabled users wherever possible.

## 2. Equivalence Above Everything

The highest accessibility objective should be equivalence.

Users should receive experiences that are:

**Functionally Equivalent**

The user can complete the same task.

**Informationally Equivalent**

The user receives the same information.

**Emotionally Equivalent**

The user can participate with comparable confidence, dignity, independence and satisfaction.

However, equivalence must never come at the expense of:

- Privacy
- Autonomy
- Dignity
- Safety

A highly personalised experience that requires extensive surveillance may achieve functional equivalence while violating ethical principles.

This is not acceptable.

## 3. Dignity Is an Accessibility Requirement

Accessibility is not merely about task completion.

Every accessibility decision should be evaluated against questions such as:

- Does this preserve dignity?
- Does this increase independence?
- Does this create stigma?
- Does this expose disability unnecessarily?
- Does this make a person feel monitored?

A technically accessible solution may still be ethically inaccessible.

# Data Collection Principles

## Collect What Is Necessary

Organisations should collect only the minimum information required to understand and improve accessibility outcomes.

The purpose should always be explicit.

Examples:

## Appropriate

- Caption usage rates.
- Text size preferences.
- Colour contrast preferences.
- Accessibility feature adoption.
- Error rates by interaction method.

## Potentially Problematic

- Long-term tracking of individual disabled users.
- Persistent disability profiles.
- Inference of medical conditions.
- Cross-service identification.
- Behavioural profiling based upon impairment.

The more specific data becomes about an individual's disability, the stronger the justification and safeguards that should be exist.

## Aggregate Before You Identify

A preferred model is:

Collect

↓

Aggregate

↓

Analyse

↓

Discard individual identifiers

Rather than:

Collect

↓

Track individuals

↓

Store indefinitely

The first supports accessibility improvement.

The second creates significant ethical and legal risk.

## Off-Estate Collection and Privacy-Preserving Analytics

An especially valuable approach is the use of privacy-preserving collection methods.

Examples include:

- Third-party analytics providers.
- Independent accessibility research organisations.
- Federated analysis.
- Aggregation at source.
- Statistical reporting before transfer.

Where possible:

User

↓

Aggregation

↓

Organisation

is preferable to:

User

↓

Raw Personal Data

↓

Organisation

This reduces risk while still providing meaningful accessibility insights.

# Understanding Accessibility Signals

## Not All Accessibility Signals Are Equal

Some user behaviours are useful accessibility indicators without being disability indicators.

### Lower-Risk Examples

- Closed captions enabled.
- Text enlargement.
- Colour adjustments.
- Reduced motion settings.
- Keyboard navigation.

These features are used by:

- Disabled users.
- Neurodivergent users.
- Older users.
- Non-native language speakers.
- Users in noisy environments.
- Users in quiet environments.
- Users with temporary impairments.

Their use should generally be interpreted as an accessibility preference rather than evidence of disability.

### Higher-Risk Examples

Some data points are more sensitive.

Examples include:

- Audio description usage.
- Screen reader usage.
- Refreshable braille displays.
- Alternative input devices.
- Eye tracking systems.

These may reveal specific impairment categories.

Additional governance should therefore apply.

Data concerning these technologies should generally be:

- Aggregated.
- Pseudonymised.
- Access-controlled.
- Time-limited.

The objective should be improving systems rather than identifying users.

# Customers Versus Research Participants

## Customers

Customers use services for real-world purposes.

Data collection should be:

- Transparent.
- Proportionate.
- Relevant to service delivery.
- Subject to clear governance.

The organisation's obligation is to improve outcomes while respecting privacy.

## Research Participants

Research participants deliberately contribute information for learning and improvement.

They may:

- Join usability studies.
- Participate in interviews.
- Take part in accessibility testing.
- Join advisory panels.

Participation requires:

- Clear informed consent.
- Clear purpose limitation.
- Ability to withdraw.
- Transparency of outcomes.

## Usability Versus Learnability

Organisations frequently combine these concepts incorrectly.

### Usability

Can users complete tasks effectively?

### Learnability

Can users understand and become proficient over time?

These are different questions.

A panel of disabled participants who are not customers may provide valuable usability insight.

However, they may provide less reliable information about:

- Long-term use.
- Real-world workflows.
- Organisational context.
- Learning journeys.

This does not invalidate their contributions.

It simply means research findings must be interpreted appropriately.

Accessibility evidence should ideally combine:

- Customers.
- Disabled non-customers.
- Subject matter experts.
- Accessibility professionals.
- Community representatives.

# Inclusive Data Is Broader Than Disability

Organisations should recognise that accessibility needs do not exist solely within disability categories.

People may experience accessibility barriers because of:

## Situational Factors

Examples:

- Carrying children.
- Driving.
- Cooking.
- Wearing gloves.
- Effects of prescription drugs.
- Lower energy levels.

## Environmental Factors

Examples:

- Bright sunlight.
- Low light.
- Loud environments.
- Poor connectivity.
- Battery preservation modes.

## Social Factors

Examples:

- Quiet environments requiring captions rather than audio.
- Shared spaces where loud output is inappropriate.
- Public transport use.
- Professional settings.
- Intoxication from alcohol.

## Emerging Technology Factors

Examples:

- Smart glasses.
- Mixed reality devices.
- Voice interfaces.

Technology that is technically accessible can still be socially inappropriate in certain contexts.

Accessibility design should account for both capability and context.

# Accessibility Evidence Should Never Come From A Single Group

Accessibility improvements frequently involve trade-offs.

A solution benefiting one group may unintentionally disadvantage another.

Examples include:

- Typography choices.
- Colour choices.
- Content simplification.
- Motion reduction.
- Navigation patterns.

Therefore all major accessibility decisions should be supported by evidence from multiple populations.

These should include combinations of:

- Blind people.
- Low vision users.
- Deaf people.
- Hard-of-hearing people.
- Neurodivergent users.
- Mobility-impaired users.
- Older users.
- Temporary impairment users.
- Situational accessibility users.

Accessibility evidence should seek optimisation across groups rather than maximisation for a single audience.

# Data and the European Accessibility Act

Accessibility measurement should be integrated into mainstream analytics and governance rather than treated as a separate activity.

Where possible, segmentation should align with recognised functional accessibility categories such as those reflected within Annex I of the European Accessibility Act.

This allows organisations to identify barriers affecting:

- Vision.
- Hearing.
- Speech.
- Physical interaction.
- Cognitive accessibility.
- Multiple impairments.

The focus should remain on functional needs rather than medical diagnosis.

The organisation generally needs to understand barriers, not conditions.

# Disability Must Never Become a Justification for Surveillance

One of the greatest ethical risks is using accessibility as a justification for excessive data collection.

Anti-patterns include:

- Collecting disability information unrelated to accessibility outcomes.
- Tracking disabled people more closely than other users.
- Using accessibility settings for behavioural advertising.
- Selling accessibility-related user data.
- Creating commercial disability profiles.

Accessibility should never become a surveillance mechanism.

# AI Training and Accessibility Data

## Ethical Uses

Accessibility data may be appropriate for AI training when:

- Collection was transparent.
- Appropriate permissions exist.
- Information is sufficiently anonymised.
- Data is representative.
- Sharing creates social value.

Examples include:

- Accessibility preferences.
- Barrier reports.
- Non-identifiable interaction patterns.
- Aggregated accessibility outcomes.
- Inclusive design research findings.

Such datasets can contribute to broader societal improvements.

## Unethical Uses

Examples include:

- Extracting screen-reader output without consent.
- Recording assistive technology sessions.
- Capturing private screen content.
- Harvesting accessibility tool interactions.
- Collecting organisational data through assistive technologies.
- Using accessibility technologies as AI data extraction tools.

People using assistive technologies should never be transformed into involuntary data sources.

The existence of a disability-related technology does not create a licence to collect additional information.

## Transparency and Data Sharing

When accessibility data is collected ethically, organisations should consider how findings can benefit wider society.

This may include:

- Publishing research findings.
- Sharing methodologies.
- Open accessibility metrics.
- Accessibility benchmark datasets.
- Industry collaboration.
- Academic partnerships.

Whenever possible, organisations should share:

Insight

not Identity

Knowledge

not Surveillance

Evidence

not Profiles

The greatest public benefit often comes from the sharing of aggregated accessibility knowledge rather than personal accessibility data.

# Governance Principles

Every accessibility data initiative should be able to answer:

1. Why are we collecting this?
2. Who benefits?
3. Could this be achieved with less data?
4. Could this be achieved with aggregated data?
5. Would disabled people consider this fair?
6. Would we be comfortable publicly explaining this activity?
7. Does it preserve dignity?
8. Does it preserve autonomy?
9. Does it improve accessibility outcomes?
10. Could this create harm if misused?

If these questions cannot be answered convincingly, the collection activity should not proceed.

## Final Principle

The ethical use of accessibility data is not about learning everything possible about disabled people.

It is about learning enough to remove barriers.

The best accessibility data practices generate insight without intrusion, improve experiences without surveillance, and create equivalence without compromising privacy, dignity, autonomy or trust.

Accessibility data should ultimately serve people, not profiles.
